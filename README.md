# 校园失物招领

基于王智洋（102402136）、庄剑钇（102402152）的需求博客和手机原型，实现可在浏览器体验的校园失物招领页面。


## 完整本地应用（账号、接口、数据库）

需要 Node.js **24.19+（24.x）**，在项目目录执行：

```powershell
npm.cmd ci
npm.cmd start
```

打开终端打印的 `http://127.0.0.1:3000`。注册账号后即可发布、上传图片和收藏。设置中可修改昵称、头像和密码；详情中的发布者可进入公开个人主页，展示真实发布统计。注册时下载保存账号恢复码，忘记密码时使用恢复码重设密码。普通账号或学号不是学校身份认证。

首次运行默认保存七条演示发布、三条急寻公告和五位发布者到数据库。可以注册自己的账号，也可以使用下列账号体验已有发布与收藏：

| 账号 | 密码 | 内容 |
| --- | --- | --- |
| `demo_student` | `CampusDemo123!` | 叶同学：三条发布（含一条已完成）、两条收藏 |
| `demo_lin` | `CampusDemo123!` | 林同学：雨伞寻物、一条收藏 |

演示内容使用默认配图与示意联系方式。修改或删除会保存，重启不会重复添加或还原；已有个人数据保留。若账号名称已被使用，会给新演示账号加 `_2` 等后缀，启动终端显示实际账号。需要空白环境时，在新数据目录配置 `DEMO_DATA=false`；关闭开关不会删除已经导入的数据。

演示用户已填好头像、个人简介、旗山校区与常用联系方式。设置中可修改；主页公开简介和校区，常用联系方式仅本人可见，新发布会自动带入。已有演示数据库会一次性补齐空白资料，用户自填内容保留。

SQLite 数据库在 `var/campus.sqlite`，头像与物品图片在 `var/uploads/`，重启后保留。此版本**不进行公网部署**。HTTP 网页使用真实 API；直接双击 HTML 保留原静态作业体验，两种数据互不混用。用 Python 等其他 HTTP 服务打开网页不会提供后端，请用 `npm.cmd start`。

完整运行、接口、小程序接入、管理员和备份说明见 [本地后端说明](docs/local-backend.md)。小程序目前可复用接口，原生页面和微信登录尚未实现。


## 静态作业体验

下载或克隆整个项目，保留目录结构，用 Chrome 打开根目录 `index.html`。页面没有 CDN、外部字体或运行时依赖，不需要安装 npm 包或启动后端。

## 静态体验步骤

1. 首页初始有七条信息；物品卡片和急寻公告使用默认配图。公告可左右滑动，查看丢失时间、地点、酬谢金额并进入详情。
2. 输入物品名称并点击搜索。点击搜索框显示最近搜索，可点历史词重新搜索；最多保留八条，重复搜索移到最前。
3. 首页只显示“寻物、招领、收藏”三个快捷筛选按钮；寻物和招领再次点击可取消，收藏可组合使用。点击右侧漏斗图标展开地点与分类多选、丢失/拾取日期范围和发布时间排序，点击“应用筛选”后生效并保持展开，内容可上下滑动，点击漏斗收起。寻物卡片为暖杏色，招领卡片为浅绿色。
4. 点击物品卡片进入详情，查看事件发生时间、描述、联系方式并收藏。
5. 寻物可选择多个可能丢失区域，展示时注明“模糊范围”；补充“最有可能的地点”。招领保留单一拾取区域。进入“发布信息”，选择寻物或招领，填写必填项；事件时间可填写具体时间或大致日期，描述选填，不要求上传照片。
6. 发布成功后进入“我的发布”，可编辑、标记完成、取消完成或删除；“收藏”选项可查看所有收藏的记录。
7. 寻物完成后显示“已找到”；招领完成后显示“已归还”。“我的发布”中可用“已完成”按钮与寻物/招领组合筛选。首页和收藏卡片显示事件时间，详情与我的发布同时显示发布时间。
8. 紧急公告突出物品、丢失时间、地点和酬谢金额；可左右滑动，也可用箭头或圆点切换。“联系我们发布紧急”显示运营团队示例联系方式，暂不提供真实公告申请服务。
9. 在“我的 → 设置”中调整默认排序、开关最近搜索记录、清空搜索记录和收藏、恢复示例数据。设置保存在当前浏览器；清空收藏和恢复示例需确认。

七条示例中的白色保温杯、高等数学课本和一串钥匙属于演示用户“我”，可用于管理流程测试。其他四条属于其他演示用户，不提供编辑入口。所有示例联系方式都是无效示意文字，请勿尝试真实联系。

复制成功后请在应用外联系发布者；若浏览器拒绝剪贴板权限，页面提示手动复制并选中联系方式。

## 静态体验数据边界

- 固定本地演示用户，没有账号系统、服务端、数据库或跨用户同步。
- 数据和收藏保存在当前浏览器的 localStorage。保存时若检测到另一页面已更新数据，会阻止旧页面覆盖并提示刷新。换浏览器、换网址或移动文件位置可能使用不同的存储；清除浏览器站点数据也会清除记录。
- 浏览器身份判断只是演示归属逻辑，不是生产环境的身份鉴权。
- 初始配图不是实物照片。本版不提供图片上传、即时聊天、地图或分享链接。
- 编辑不能改变发布类型，完成后可取消“已找到”或“已归还”，恢复为进行中。
- 删除和恢复示例会清除本地数据，操作前有确认对话框。
- 存储损坏时保留原数据并显示提示；只有明确选择恢复示例后才覆盖。保存失败不会把未保存的操作显示为成功。

```text

js/app.js                    页面导航、表单和交互控制

server/                      本地 API、SQLite、图片上传、管理员与备份
e2e/                         Chrome 真实多账号端到端测试

tests/security.test.cjs      用户文本、显示语义与示例数据检查
tests/interactions.test.cjs  筛选草稿、应用与日期错误的控制器交互检查
```

`data.js` 使用浏览器全局对象与 CommonJS 双入口，页面采用普通脚本而非 ES 模块，以便保持静态文件交付方式。

## 开发检查

自动测试使用 Mocha 和 Node 内置的 `node:assert/strict`。开发检查需要 Node.js 24.19+（24.x）。在项目目录安装开发依赖后执行：

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run check
```

自动化测试共保留 26 个核心用例：`npm test` 运行 19 个业务、接口、视图和演示数据用例；`npm run test:browser` 运行 7 个 Chrome 页面流程用例。开发时可执行 `npm.cmd run test:watch` 自动重跑；也可以执行 `npm.cmd test -- --grep "favorite"` 只运行名称含 `favorite` 的用例。

Mocha 仅用于开发测试，直接打开 `index.html` 不需要 Node.js 或安装依赖。测试方法及用例设计见 [测试说明](docs/testing.md)。

测试覆盖表单校验、关键词与组合筛选、事件日期范围、收藏、发布权限、完成与取消、资料与统计、删除、持久化、图片上传及底栏固定。自动化测试代替不了浏览器中的布局、剪贴板和完整页面走查。
