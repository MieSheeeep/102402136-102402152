# 校园失物招领 · 本地 MVP

基于王智洋（102402136）、庄剑钇（102402152）的需求博客和手机原型，实现可在浏览器体验的校园失物招领页面。

## 打开项目

下载或克隆整个项目，保留目录结构，用 Chrome 打开根目录 `index.html`。页面没有 CDN、外部字体或运行时依赖，不需要安装 npm 包或启动后端。

如果你希望使用本地 HTTP 预览，可在项目目录执行：

```powershell
python -m http.server 5173 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:5173/`。Python 仅用于这种可选预览方式。

本轮自动验证涵盖数据逻辑及 JavaScript 语法。浏览器走查的实际情况见 [验证记录](docs/mvp-verification.md)，不要把未完成的浏览器检查当成已通过。

## 如何体验

1. 首页有六条明确标为“示例”的信息；全部使用同一张默认配图。
2. 输入物品名称并点击搜索。点击搜索框显示最近搜索，可点历史词重新搜索；最多保留八条，重复搜索移到最前。
3. 首页只显示“寻物、招领、收藏”三个快捷筛选按钮；寻物和招领再次点击可取消，收藏可组合使用。点击右侧漏斗图标展开地点与分类多选、丢失/拾取日期范围和发布时间排序，点击“应用筛选”后生效并保持展开，内容可上下滑动，点击漏斗收起。寻物卡片为暖杏色，招领卡片为浅绿色。
4. 点击物品卡片进入详情，查看事件发生时间、描述、联系方式并收藏。
5. 寻物可选择多个可能丢失区域，展示时注明“模糊范围”；补充“最有可能的地点”。招领保留单一拾取区域。进入“发布信息”，选择寻物或招领，填写必填项；事件时间可填写具体时间或大致日期，描述选填，不要求上传照片。
6. 发布成功后进入“我的发布”，可编辑、标记完成、取消完成或删除；“收藏”选项可查看所有收藏的记录。
7. 寻物完成后显示“已找到”；招领完成后显示“已归还”。“我的发布”中可用“已完成”按钮与寻物/招领组合筛选。首页和收藏卡片显示事件时间，详情与我的发布同时显示发布时间。
8. 紧急公告突出物品、丢失时间、地点和酬谢金额；可左右滑动，也可用箭头或圆点切换。“联系我们发布紧急”显示运营团队示例联系方式，暂不提供真实公告申请服务。
9. 在“我的 → 设置”中调整默认排序、开关最近搜索记录、清空搜索记录和收藏、恢复示例数据。设置保存在当前浏览器；清空收藏和恢复示例需确认。

六条示例中的白色保温杯、高等数学课本和一串钥匙属于演示用户“我”，可用于管理流程测试。其他三条属于其他演示用户，不提供编辑入口。所有示例联系方式都是无效示意文字，请勿尝试真实联系。

复制成功后请在应用外联系发布者；若浏览器拒绝剪贴板权限，页面提示手动复制并选中联系方式。

## 数据边界

- 固定本地演示用户，没有账号系统、服务端、数据库或跨用户同步。
- 数据和收藏保存在当前浏览器的 localStorage。保存时若检测到另一页面已更新数据，会阻止旧页面覆盖并提示刷新。换浏览器、换网址或移动文件位置可能使用不同的存储；清除浏览器站点数据也会清除记录。
- 浏览器身份判断只是演示归属逻辑，不是生产环境的身份鉴权。
- 初始配图不是实物照片。本版不提供图片上传、即时聊天、地图或分享链接。
- 编辑不能改变发布类型，完成后可取消“已找到”或“已归还”，恢复为进行中。
- 删除和恢复示例会清除本地数据，操作前有确认对话框。
- 存储损坏时保留原数据并显示提示；只有明确选择恢复示例后才覆盖。保存失败不会把未保存的操作显示为成功。

## 目录说明

```text
index.html                   页面入口、主导航、对话框和反馈容器
assets/default-item.svg      全站共用的默认物品插画
css/styles.css               视觉样式与桌面／手机适配
js/data.js                   业务规则和本地存储
js/seed.js                   初始演示数据
js/views.js                  页面渲染、图标和文本转义
js/app.js                    页面导航、表单和交互控制
tests/data.test.cjs          自动化业务测试
tests/security.test.cjs      用户文本、显示语义与示例数据检查
tests/interactions.test.cjs  筛选草稿、应用与日期错误的控制器交互检查
package.json                可选的开发检查命令，无依赖
docs/                       来源、需求、实现计划和验证记录
```

`data.js` 使用浏览器全局对象与 CommonJS 双入口，页面采用普通脚本而非 ES 模块，以便保持静态文件交付方式。

## 开发检查

自动测试使用 Node 内置的 `node:test` 和 `assert`，不依赖第三方测试框架。安装 Node.js 后在项目目录执行：

```powershell
npm.cmd test
npm.cmd run check
```

也可以直接执行 `node --test tests/*.test.cjs`。

测试覆盖校验失败、关键词与组合筛选、排序、收藏、编辑归属、状态文案、删除、持久化、损坏数据与存储失败。自动化测试代替不了浏览器中的布局、剪贴板和完整页面走查。

## 结对协作

建议一人维护 `index.html`、`css/styles.css`、`js/views.js`，另一人维护 `js/data.js`、`js/seed.js` 和测试；共同审阅 `js/app.js` 的连接逻辑。实际分工由两人确认。

按课程要求，另一位成员 fork 主仓库，通过 PR 提交真实进展；按功能完成情况逐步 commit。当前文件由助手协助生成，不能当成两人已经完成的提交或互审记录。
