# Mocha 测试说明

项目使用 Mocha 和 Node.js 内置 `node:assert/strict`，保留29个核心用例：22个业务、视图、接口及演示数据测试和7个浏览器流程测试。同一功能的边界输入合并在一个用例中，保留关键断言，没有使用跳过标记或隐藏运行配置缩减数量。

## 运行

需要 Node.js 24.19+（24.x）；浏览器测试需要已安装 Chrome。

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run test:browser
npm.cmd run check
```

`npm test` 成功显示 `22 passing`；`npm run test:browser` 成功显示 `7 passing`。失败时会显示用例名称与断言差异，并返回非零退出码。`check` 检查应用和后端脚本语法。

```powershell
# 开发时自动重跑业务与接口用例
npm.cmd run test:watch

# 只检查收藏相关用例
npm.cmd test -- --grep "favorite"
```

业务用例以合法／非法输入及成功／拒绝路径检查核心逻辑；浏览器用例检查页面连接这些逻辑后的实际行为。当前未统计代码覆盖率，不将通过数量等同于完整覆盖。

## 对照原型设计

选取依据是仓库中的 [原型设计博客正文存档](references/blog-extract.md)「主要功能与原型设计」和「用户使用流程」，对应关系如下。

| 原型功能／流程 | 自动检查 |
| --- | --- |
| 首页／发布／我的三个入口 | 手机和桌面页面切换时底栏固定，不横向溢出 |
| 关键词及地点、时间、类型筛选 | 名称搜索、多选组合和事件日期范围；类型选择与两类信息状态由发布、状态用例检查 |
| 信息详情与收藏 | 发布后其他账号可看详情、图片和收藏；联系方式仅对登录用户开放 |
| 寻物／招领发布及必填校验 | 合法输入、必填项缺失、发布初始状态、真实图片上传和发布反馈 |
| 我的发布、编辑信息 | 发布归属、编辑内容与图片保留、其他账号不能修改或删除 |
| 找回后的状态修改 | 完成与取消确认、个人主页完成数量更新 |
| 原型之外后续增加的账号与资料 | 注册登录、退出、资料隐私、头像昵称及统计、数据库持久化 |

复制联系方式与视觉细节由人工验收补充；本表不表示所有原型操作均已有自动测试。

## 数据隔离与人工检查

接口及浏览器测试使用系统临时目录，结束后清理，不写入项目的 `var` 数据库。直接打开 `index.html` 不需要安装 Mocha；静态 HTML 入口改由人工检查。

当前检查缺少图片字段的旧记录兼容、图片大小限制和非法图片，但不覆盖全部旧数据迁移、浏览器存储配额耗尽、恢复码、备份恢复、所有动画细节及网络异常。演示前仍应人工走查账号恢复、公告和急寻申请、浏览偏好、弹窗、剪贴板与手机输入体验。

较早验证文档中的 60、84 或 16 等数量是当时的测试记录；当前用例数量以本页和实际运行结果为准。
