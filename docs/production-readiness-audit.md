# 上线升级范围与现状检查

日期：2026-10-07。本文记录现状与待决策事项，不表示正式版已经完成或部署。

## 本轮决策与完成范围

用户已确认无需公网部署，采用“网页／未来小程序 → 后端接口 → 数据库和图片存储”。保留网页并实现本地真实后端；为减少外部服务依赖，采用账号＋密码、恢复码、SQLite 和本地图片目录。以下“当前实现与缺口”表记录升级前的检查结果，不能当成本轮完成后的状态。

本轮已经实现注册／登录／注销／密码修改／恢复码找回、服务端权限、发布与收藏持久化、图片上传及归属检查、昵称头像修改、发布者公开主页与统计、公告及急寻审核、管理员内容删除、数据备份脚本。具体启动与 API 见 [本地后端说明](local-backend.md)。

实际微信登录和小程序页面、学校认证、邮件服务及公网部署未纳入本轮实现。此前的 PostgreSQL／Better Auth 候选已被本地 SQLite／scrypt 会话方案替代，未安装或宣称接入这些候选组件。

## 已确认的升级需求

- 设置中修改个人昵称、上传和更换头像。
- 发布详情展示发布者头像和昵称，可进入公开个人主页。
- 个人主页展示公开发布列表及实际发布、进行中、已完成等统计。
- 支持真实多用户注册、登录和服务端持久化，完成可部署版本。

## 当前实现与缺口

| 范围 | 当前状态 | 正式版需要 |
| --- | --- | --- |
| 身份 | `js/app.js` 固定当前用户为 `me` | 真实用户、登录会话、注销、找回密码 |
| 数据 | 浏览器 localStorage 保存整份状态 | 服务端数据库及跨设备一致数据 |
| 权限 | 前端检查发布者 ID | 服务端从会话识别用户，检查每次读写权限 |
| 个人资料 | 发布记录保存 `ownerName`，没有独立用户资料表 | 用户资料表，按用户 ID 关联最新昵称和头像 |
| 图片 | 所有物品共用默认 SVG | 真实头像和物品图片上传、持久化与替换 |
| 收藏 | 当前浏览器中的 ID 数组 | 用户与物品之间的数据库关联，保证唯一性 |
| 公告 | 前端写死若干物品 ID 与酬谢金额 | 可管理的公告记录、发布/撤下与过期处理 |
| 管理 | 只有本地重置 | 管理员公告管理、内容处理与账号管理 |
| 交付 | Chrome 可直接打开静态 HTML | 正式服务部署、HTTPS、环境配置、迁移与恢复说明 |
| 测试 | Mocha 60 项业务/视图/模拟控制器测试 | 数据库和接口集成测试、真实多账号浏览器流程 |

## 建议的公开资料规则

- 公开昵称、头像、加入时间、公开发布列表，以及数据库计算的发布、进行中、已完成数量。
- 个人收藏、登录邮箱和账号安全设置由本人查看。
- 发布记录引用稳定用户 ID；更改昵称或头像后，历史记录同步显示最新资料。
- 统计中的已完成来自发布者更新状态，不能直接视为第三方确认的信誉评分。
- 联系方式在帖子详情中的访问规则需在登录方案确定后明确。

## 实现路线候选

1. 沿用当前页面与样式，增加 Node.js API、PostgreSQL、成熟认证组件与图片存储。可以优先复用当前 UI 和纯数据规则。
2. 同时迁移 React 并增加后端。组件化有利于后续扩展，但需要重新验证现有筛选、公告和收藏动效。
3. 使用托管认证、数据库和对象存储。减少自行维护的服务，部署选择会受服务地区和供应商能力影响。

建议优先路线 1；最终技术选型依赖登录方式和部署环境。

## 初始待决策项（本轮已确定）

- 登录方式：采用普通账号与密码，使用恢复码找回；未接入学校认证或邮件服务。
- 部署环境：用户明确无需公网部署，完成本地服务和可复用 API。

## 上线验收方向

- 两个真实用户可以跨设备登录；A 发布后 B 可浏览、收藏，B 不能修改 A 的帖子。
- 修改昵称和头像后，详情与公开个人主页同步更新；统计与可见列表口径一致。
- 登录、注销、过期会话、验证及找回流程可验证；密码和会话由认证组件处理。
- 数据、图片在服务重启后保留；数据库迁移、备份与恢复经过实际验证。
- 保留当前静态版本的课程交付入口；正式版运行说明独立说明服务和数据库依赖。
